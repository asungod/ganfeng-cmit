## 2. 核心算法怎么讲

### 2.1 约束表与改锁（最重要）
- 每条线是一张二维表：列 × 行 → 合 / 勉 / 冲。例：瓷语的列是朝代，行是釉色。
- 访客选了（宋，粉彩），`lookup` 返回 conflict，再用 `fallbackRow` 取宋代的推荐釉色「影青」，自动改过去。
- 界面用箭头动画回放「冲突格 → 规则条目 → 改锁格」，可以重放。
- **为什么不用大模型判断？** 表是可以打印、审计、逐格追责的。大模型的判断不可复现，也给不出出处。
- **合 / 勉 / 冲谁定的？** 瓷语依据故宫博物院等词条；阁序依据原文句子归属，「冲」是设计约定；客家是叙事约定，空间要素有出处。界面上分别盖章。

### 2.2 展示 → 验证
- 「展示」：审计面板只摘录已核出处的原文，附 URL 和访问日期。
- 「验证」：每条规则配命中、边界、例外三个案例。「试一下」会先把表恢复成默认，再执行这个组合，然后比较「依据预期」和「实测」。
- 如果有人改了表，面板会显示不一致。这说明验证是真的在运行，不是写死的文字。

### 2.3 问展检索（`agent.ts` 的 `ask()`）
顺序如下：
1. 问题和纸条完全一致 → 直接给答案。
2. 短追问（含「那 / 为什么 / 呢」等）→ 拼接上一问再检索。
3. BGE 向量检索：
   - 查询加前缀「为这个句子生成表示以用于检索：」，取均值池化并归一化，得到 512 维向量。
   - 每条题库有两个向量：全文（问题 + 答案 + 关键词）和只含问题的向量，取两者余弦的较大值。
   - 当前展区的条目加 0.04；问句里每出现一个该条的主题词（滕王、影青……，不算「为什么」「谁」这类泛词），再加 0.04，最多加 0.08。
   - 最高分 ≥ `DOC_SCORE_THRESH = 0.55` 才作答。
   - 追问拼接有例外：问句里已经带了某条的主题词，就不算追问，不拼上一问。
4. 词面检索回退：关键词打分，当前展区加 0.35，≥ 2.1 才作答。
5. 都没命中 → 拒答：「题库未收录这一问……不把句子送去外部大模型」。

意图槽位（把一句话写进朝代、釉色等槽位）：
- 用原型短语向量匹配，阈值 `PROTO_SCORE_THRESH = 0.40`。
- 第一名与第二名的差距小于 `PROTO_SCORE_MARGIN = 0.04` 时不填，避免模棱两可。

**两个阈值，别说混：**
- 槽位阈值 0.40：在自建的 58 条金标问上扫描 0.20～0.40，0.40 时召回 87.6%、精确 82.8%，F1 最高（`public/thresh-bench.json`，2026-09-04）。
- 作答阈值 0.55：标定集 101 问（题库内改写问 61、题库外问 40），见 `docs/calib/README.md`。
  - 原来的作答阈值 0.42 会把「今天股市怎么样」这类题库外问题答出来，所以重新标定。
  - 0.55 是在 dev 47 问上选定的：召回 100%，题库外 0 误答。
  - 另外写了 54 问 holdout，只用来检验：召回 88.2%，精确 78.9%；题库外 20 问里误答 4 问，全部是同主题难例（滕王阁门票、鄱阳湖面积、青花瓷价格、围屋现在有没有人住）。
  - 全部 101 问上 F1 最高的也是 0.55（0.905）。
- **要主动承认**：问句都是开发时自己写的，不是独立测试集；同主题、问法不同的问题会被答成同主题的题库条目。答案都附出处卡，观众能看出答的是哪一条。

### 2.4 离线与安全
- 模型从本地 `/models/` 加载，代码里设了 `allowRemoteModels = false`。
- WASM 推理引擎在 `/ort/`，单线程运行。
- 服务器只监听 127.0.0.1。
- 不能直接双击 index.html：file:// 下浏览器会拦截 WASM 和模块脚本。

- 景德镇手工制瓷技艺：国家级非遗，2006 年第一批，编号 Ⅷ-7（中国非物质文化遗产网）。

## 4. 可能被问到的问题
1. **这和直接用 ChatGPT 讲解有什么区别？** 答案只来自有出处的题库，题库外拒答；判定由可审计的表完成，可以复现。
2. **合 / 勉 / 冲会不会太主观？** 对规则分了三类并逐一盖章。「勉」用来表达学界有不同看法或过渡期，例如元代祭红、元代五彩（后者在面板上标为「边界」，承认可以质疑）。
3. **为什么渔舟和雁阵是冲？它们明明是同一联。** 这是设计约定：一个情境只锁一个地名锚点（彭蠡 / 衡阳）。不是史实断言，面板写明了。
4. **BGE 阈值怎么来的？可靠吗？** 见 2.3，并主动说明局限。
5. **AI 做了多少？你做了什么？** 如实说明：大部分代码由 AI 编程助手按你的要求生成；通义千问提评审意见；运行时只有非生成式的 BGE。你的贡献【请准备 3～5 条具体事例：做了哪些决策、否决过哪些方案、亲自核对过哪些出处、做过哪些测试】。
6. **为什么离线？** 展厅和教室网络不稳定；不收集数据；评审时更容易运行。
7. **第三方资源合规吗？** 全部是 MIT、Apache-2.0 或 OFL；字体子集随包附 OFL 许可原文；没有使用文物照片。
8. **下一步做什么？** 补一手出处，请专业老师审校，做观众测试和独立评测集，给题库外难例加「答非所问」检测，扩展主题。
9. **测试怎么做的？** 用 headless Chrome（软件渲染）跑端到端回归：三条线逐个点釉色 / 情境按钮，点遍全部 24 个「试一下」，各问一个题库内问题和一个题库外问题。结果 24/24 ✓，页面无异常（`docs/e2e-2026-10-08.log`）。

## 4.5 阶段 3 真机回归修掉的 bug（被问「测过吗」时可以举）
1. **切换展柜后监听泄漏**：三个展柜都把 click 监听挂在同一个 `#app` 容器上，卸载时没有移除。切换展柜后，旧展柜的处理器还在响应，比如在阁序里点「试一下」会触发瓷语的处理器并报错。修法：`src/main.ts` 每次挂载前用一个新的空容器替换 `#app`。
2. **客家平面图点房间无效**：外层 `.exhibit` 带着 `data-hour` 属性，时辰按钮的处理器用 `closest("[data-hour]")` 匹配，吞掉了所有点击。修法：改成 `closest("button[data-hour]")`。
3. **瓷语釉色 / 朝代按钮没有同步审计面板的选择**：审计面板显示的还是旧规则。修法：点按钮时同时更新 `pickEra` / `pickGlaze`。
4. **题库外问题被答出来**：作答阈值 0.42 太低。修法：重新标定为 0.55，并加问句向量和主题词加权。
5. 画面：阁序改成曲面屋顶、斗拱、栏杆、层叠山脊和乌篷船；客家室内加了夯土材质、椽子和光影；竖排对联改为逐字直立。
